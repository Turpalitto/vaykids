# Нохчийн мотт — учим чеченский язык

Детское offline-first приложение для изучения чеченского языка: карточки, мини-игры, карта локаций, ежедневная практика, награды и защищённая родительская зона. Построено на Next.js App Router, Tailwind CSS 4, Zustand, Drizzle ORM и PostgreSQL.

## Что уже готово

- локальный прогресс с миграцией и защитой от повреждённого `localStorage`;
- PWA/offline shell: приложение устанавливается на телефон, встроенный словарь и прогресс работают без БД;
- понятный статус синхронизации: данные сначала сохраняются локально, серверная синхронизация выполняется позже;
- ежедневная серия по локальному календарю устройства, а не по UTC;
- игры `memory`, `what`, `word`, `sentence`, `find` и составной `daily`;
- доступность: крупные зоны нажатия, клавиатурный focus, `aria`-состояния, свободный масштаб страницы и reduced motion;
- серверные error/loading/not-found состояния и безопасные HTTP-заголовки;
- родительская зона с одноразовым серверным challenge и HttpOnly-сессией;
- ручные правки карточек и список проверки носителем языка через PostgreSQL;
- встроенные тесты целостности словаря.

## Быстрый старт

```bash
npm install
cp .env.example .env       # DATABASE_URL можно оставить пустым для локального режима
npm run dev                 # локально: http://127.0.0.1:3000
```

PostgreSQL нужен только для синхронизации между устройствами, ручных правок карточек и проверки контента:

```bash
npm run db:push
```

Сборка и запуск без `DATABASE_URL` тоже поддерживаются. API синхронизации в этом случае отвечает `503`, а ребёнок продолжает работать на локальных данных. `/api/health` — liveness, `/api/health?ready=1` — readiness с обязательной проверкой PostgreSQL.

## Скрипты

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Dev-сервер Next.js |
| `npm run build` | Продакшн-сборка без обязательной БД |
| `npm run start` | Запуск production-сборки |
| `npm run lint` | ESLint |
| `npm run typecheck` | Проверка типов TypeScript |
| `npm test` | Vitest: проверки целостности данных |
| `npm run db:push` | Создать/обновить таблицы по `src/db/schema.ts` |
| `npm run db:generate` | Сгенерировать SQL-миграции в `drizzle/` |
| `npm run db:studio` | Drizzle Studio |

Для production обязательно задайте длинный случайный `PARENT_SESSION_SECRET`. Если переменная не задана, сервер использует случайный секрет процесса: это безопасно для локальной разработки, но сессии родительской зоны будут сбрасываться после перезапуска.

## Архитектура

```
src/
  app/                  страницы App Router, boundaries и API
    api/                health · profiles · progress · overrides · review · parents
    play/[game]/        игры и ежедневная очередь
  components/           UI-компоненты, app bootstrap и механики игр
  data/                 статический словарь, темы, сцены и UI-строки
  db/                   схема Drizzle и необязательное подключение PostgreSQL
  lib/
    store.ts            Zustand, миграция, локальный прогресс и sync queue
    useContent.ts       карточки с учётом серверных правок
    validation.ts       Zod-схемы API
    parent-auth.ts      challenge и подписанная HttpOnly-сессия родителей
    audio.ts            короткие WebAudio-сигналы без внешнего TTS
public/
  manifest.webmanifest  PWA-метаданные
  sw.js                 offline shell и cache strategy
```

## Контент и проверка носителем

Слова, требующие подтверждения носителем чеченского, помечены полем `review:` в `src/data/topics/*.ts`. Автоматический чек-лист — **`review-checklist.md`**. После подтверждения: исправьте `che` в файле темы и снимите флаг `review`.

Для новых слов:

- используйте уникальный `id`;
- добавляйте карточку в `src/data/topics/<тема>.ts`;
- проверяйте сцену, emoji/иллюстрацию и пример предложения;
- запускайте `npm test`, `npm run typecheck` и `npm run lint`.

Чеченская буква `Ӏ` в коде может записываться как `1` — хелперы `P()` нормализуют её автоматически.

## Ограничения и следующий production-этап

Проект уже устойчив как локальное детское приложение, но перед публичным multi-user запуском нужны отдельные продуктовые решения:

1. полноценные аккаунты родителей и серверная авторизация профиля вместо локальных anonymous ID;
2. серверная модель конфликтов/версий прогресса и удаление данных по запросу;
3. аналитика только с родительским согласием, без рекламных SDK и без трекинга ребёнка;
4. библиотека проверенных записей носителей, после чего можно безопасно вернуть озвучку;
5. автоматические visual/e2e проверки на мобильных viewport и CI с preview deployment;
6. отдельная CMS/content pipeline для версий словаря, локалей и аудио.

Родительская зона уже закрывает mutation API серверной HttpOnly-сессией. Публичные профили и прогресс пока остаются anonymous-by-design для offline-сценария; это не следует считать полноценной авторизацией.
